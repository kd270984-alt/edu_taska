# Таска · учебная версия

Планировщик задач команды: один экран — календарь. У каждого человека свои задачи,
задачи можно поручать друг другу, переносить по дням, обсуждать и складывать в архив.

Продукт ставится на ваш сервер целиком: база, хранилище файлов, API и веб-страница.
Ничего внешнего, кроме адреса вашего сайта, не нужно.

---

## Что внутри

| Часть | Что это |
|---|---|
| `web/index.html` | всё приложение: календарь, карточки задач, поиск, архив, профиль |
| `api/` | сервер: вход, задачи, метки, комментарии, вложения, пользователи |
| `api/migrations/` | схема базы (применяется сама при первом запуске) |
| `docker-compose.yml` | весь стек: PostgreSQL, MinIO, API, Caddy |
| `Caddyfile` | веб-сервер: раздаёт страницу, проксирует `/api` и `/ws`, сам получает HTTPS |
| `scripts/first-login.sh` | адрес, логин и пароль первого входа — три строки |
| `scripts/admin-password.sh` | новый пароль администратору, ничего не стирая — те же три строки |
| `scripts/demo-reset.sh` | стереть всё и посадить демо-команду заново (с новым паролем) |
| `scripts/check-web.js` | проверка фронта перед выкладкой (ловит битый JS) |
| `scripts/backup.sh`, `scripts/restore.sh` | ночная копия базы и возврат из копии |
| `scripts/laptop/` | копия на ноутбук: установщики для Mac и Windows (см. «Копия на ноутбук») |
| `scripts/crm-demo.sh` | учебный раздел «CRM»: включить, выключить, загрузить пример |

## Что нужно на машине

- Docker и Docker Compose (Docker Desktop на Mac/Windows, `docker` + плагин compose на Linux)
- 2 ГБ свободной памяти и 5 ГБ диска
- Для сервера: адрес, по которому его видно из интернета (свой домен или бесплатный `sslip.io`),
  и открытые порты 80 и 443

## Запуск на своей машине (5 минут)

```bash
cp .env.example .env
```

Откройте `.env` и заполните пустые строки. Пароли придумайте любые длинные, например так:

```bash
openssl rand -hex 24
```

Заполнить нужно `POSTGRES_PASSWORD` (тот же пароль подставьте внутрь `DATABASE_URL`),
`MINIO_ROOT_PASSWORD` и `JWT_SECRET`. Остальное на своей машине оставьте как есть.

```bash
docker compose up -d
```

Первый запуск качает образы — это пара минут. Готово, когда команда ниже отвечает `"ok":true`:

```bash
curl http://127.0.0.1:8088/api/health
```

Откройте **http://localhost:8088**.

При первом запуске Таска сама заводит демо-команду — трёх вымышленных сотрудников с задачами
(см. «Демонстрационные данные» ниже) — и придумывает пароль администратору. Адрес, логин и пароль:

```bash
bash scripts/first-login.sh
```

Ответ — три строки:

```
Адрес вашей Таски: http://localhost:8088
Логин: admin
Пароль: xxxx-xxxx-xxxx
```

Войдите и сохраните пароль в менеджере паролей. Сменить его можно в профиле (щёлкните по своему
аватару слева). Остальных людей заводит администратор в разделе «Команда».

Пароль лежит в файле `api/.first-login` (права 0600, в git не попадает). В журнал он попадает,
только если этот файл при запуске записать не удалось (например, кончился диск): тогда
`first-login.sh` сам найдёт пароль в журнале, сверит его с базой и сохранит в файл.
Сменили пароль в профиле — файл стирается сам, и `first-login.sh` отвечает, что записки нет (код 3).
Пароль потерян, а записки уже нет — новый пароль, ничего не стирая: `bash scripts/admin-password.sh`
(см. «Новый пароль администратора»).

**Смена пароля и выключение обрывают прежние входы.** Сменили пароль (себе в профиле или сотруднику
карандашом в «Команде») или выключили сотрудника бегунком — все входы под этим логином на всех
устройствах перестают действовать на следующем же действии: там снова попросят войти. Свой текущий
вход при смене своего пароля остаётся. Выключенного потом включили — старые входы не возвращаются,
он входит заново по паролю. То же у телеграм-агента: `bash scripts/agent-account.sh` с новым паролем
закрывает его прежние входы, а запущенного бота сам перезапускает с новым паролем.

## Запуск на сервере

1. **Адрес.** Нужен домен, по которому сервер видно из интернета. Два пути:
   - свой домен — направьте его A-записью на адрес сервера;
   - бесплатный адрес **sslip.io** — это IP сервера, записанный через дефисы, плюс `.sslip.io`.
     Для сервера `203.0.113.10` адрес будет `203-0-113-10.sslip.io`. Подставьте цифры
     СВОЕГО сервера, не из примера. Регистрировать и настраивать ничего не нужно,
     адрес работает сразу.
2. **Папка.** Положите проект на сервер в папку `taska-edu` — например
   `git clone <адрес репозитория> taska-edu`. Имя папки важно: на `/root/taska-edu` рассчитаны
   ночная копия, копия на ноутбук и команды из раздела «Обслуживание». Тома docker называются
   `taska-edu_pgdata` (база) и `taska-edu_miniodata` (файлы задач).
3. Создайте `.env` так же, как выше, и добавьте в него:

```
APP_HOST=203-0-113-10.sslip.io      # ЦИФРЫ СВОЕГО сервера, или свой домен; без http:// и без / на конце
ACME_EMAIL=почта@для-сертификата
HTTP_BIND=0.0.0.0:80
HTTPS_BIND=0.0.0.0:443
```

4. `docker compose up -d` — Caddy сам получит сертификат Let's Encrypt.
5. Проверка. Спрашивайте сразу по `https` и по своему адресу:

```bash
curl -s https://203-0-113-10.sslip.io/api/health   # свой адрес
```

   ⚠️ По `http://` ответа не будет: Caddy отвечает переездом на `https` (код 308), и `curl`
   за переездом сам не идёт. Это не поломка — просто проверяйте по `https`.

6. Откройте `https://` и свой адрес. Замок появляется не сразу: сертификат выдаётся
   за несколько секунд после первого обращения.
7. Адрес, логин и пароль: `bash scripts/first-login.sh` (в папке Таски на сервере).

### Демонстрационные данные

Пустая система плохо показывает, на что годится. Поэтому при первом запуске Таска сама заводит
трёх вымышленных сотрудников с задачами, подзадачами, метками и комментариями — есть на что
посмотреть с первой минуты:

| Логин | Кто | Вход |
|---|---|---|
| `admin` | Анна Соколова — администратор | пароль придумывает система: `bash scripts/first-login.sh` |
| `manager` | Игорь Волков — руководитель | закрыт, пока администратор не задаст пароль в «Команде» |
| `user` | Мария Лебедева — сотрудник | закрыт, пока администратор не задаст пароль в «Команде» |

У Игоря и Марии пароля нет вовсе: им можно поручать задачи, но войти под ними нельзя. Так на
открытом адресе нет ни одного известного всем пароля.

**Нужна пустая Таска без демо** — до первого запуска поставьте в `.env` строку `DEMO_SEED=0`:
тогда Таска заведёт одного администратора с логином из `ADMIN_EMAIL`, пароль — тоже
`bash scripts/first-login.sh`. Если Таска уже запускалась, строка ничего не меняет (люди в базе
уже есть) — начать с чистого листа можно только так: `docker compose down -v` и снова
`docker compose up -d`. ⚠️ Это стирает базу и файлы задач целиком.

**Начать демо заново** (например, после занятия):

```bash
bash scripts/demo-reset.sh
```

⚠️ Он **стирает всё**: людей, задачи, метки, комментарии и вложения — включая ваших людей
и пароль администратора. Сначала показывает, сколько всего будет стёрто, и спрашивает «да/нет»;
без терминала (помощник) — только с ключом `--yes`, иначе ничего не делает (код 3). Помощник
добавляет `--yes` только после «да» человека: сам он стирание не подтверждает. В конце
печатает те же три строки с новым паролем. Учётка телеграм-агента и данные CRM остаются.

### Новый пароль администратора

Пароль администратора потерян, а `first-login.sh` отвечает, что записки нет (код 3), — стирать
ничего не нужно:

```bash
bash scripts/admin-password.sh
```

Скрипт показывает, кому задаст пароль, и спрашивает «да/нет»; без терминала (помощник) — только с
ключом `--yes`, иначе ничего не меняет (код 3). Помощник добавляет `--yes` только после «да» человека.
Ответ — те же три строки, что у `first-login.sh`: адрес, логин, пароль; новый пароль ложится в ту же
записку `api/.first-login`. Люди, задачи и вложения остаются как были. Прежний пароль перестаёт
действовать, и все открытые входы под этим логином (другие устройства, посторонний) закрываются.
Без логина пароль получает `admin`, а если его нет — администратор из `ADMIN_EMAIL`; другому
администратору — `bash scripts/admin-password.sh <логин> --yes`. Выключенному администратору и
учётке телеграм-агента скрипт пароль не задаёт и пишет почему.

### Если ставили Таску до 16.11 (был шаг «Оживить»)

Прежний шаг «Оживить» (старый `scripts/demo-reset.sh`) давал `admin`, `manager` и `user` один
общий пароль `123456` — на открытом адресе им мог войти любой. После обновления
(`git pull` и `docker compose restart api`) Таска при запуске сама проверяет эти три входа:

- у `manager` и `user` с паролем `123456` вход закрывается: пароля больше нет, задачи и
  комментарии остаются. Нужны они для показа — задайте пароль карандашом в «Команде»;
- у `admin` с паролем `123456` пароль меняется на новый случайный. Узнать его:
  `bash scripts/first-login.sh` — те же три строки: адрес, логин, пароль. Сохраните его сразу;
- кто уже сменил пароль сам — того это не касается, у него ничего не меняется.

В журнале api при этом появляется строка `ADMIN_BOOTSTRAP у admin был общий пароль 123456 …`
(без самого пароля) и строка о том, у кого закрыт вход. Повторный запуск ничего не меняет.

Входы, открытые раньше под `admin`, `manager` и `user` с паролем `123456` (на любых устройствах —
и ваши, и чужие, если кто-то успел войти по общему паролю), после обновления не работают: на первом
же действии там попросят войти заново. Вы входите с новым паролем из `first-login.sh`.

**Перед тем как открывать сервер людям — четыре дела:**

1. Войдите администратором: логин `admin` и пароль из `bash scripts/first-login.sh`. Сохраните
   пароль в менеджере паролей или смените его в своём профиле. Игорь и Мария войти не могут,
   пока вы не зададите им пароль; когда заведёте своих людей — закройте демо-сотрудникам доступ
   бегунком в «Команде» (их задачи останутся).
2. Закройте на сервере всё, кроме 22, 80 и 443:
   `ufw allow 22/tcp && ufw allow 80,443/tcp && ufw enable`.
   ⚠️ Порт 22 разрешайте ПЕРВЫМ и не пропускайте его: это SSH, без него включённый файрвол
   отрежет вас от собственного сервера. База, хранилище и API сидят во внутренней сети
   docker и наружу не смотрят.
3. Заведите резервные копии по расписанию, а не руками (см. «Обслуживание»).
4. Проверьте, что `JWT_SECRET` в `.env` — длинная случайная строка, а не оставшаяся от примера.

## Помощник в Телеграме (необязательно)

К Таске можно подключить бота: человек пишет ему в личку обычными словами — «что у меня
сегодня?», «добавь задачу позвонить клиенту на завтра в 11», «перенеси смету на пятницу»,
«заверши планёрку» — а бот делает это в Таске от его имени. Он умеет и поискать в интернете,
если вопрос не про задачи.

**Какой ключ подходит.** Боту нужна одна нейросеть, на выбор: **OpenAI**, **Claude** или **Kimi**.

| Ключ в `.env` | Строка `AI_PROVIDER` | Текст | Голосовые | Поиск в интернете |
|---|---|---|---|---|
| `OPENAI_API_KEY` | `openai` (или строки нет) | да, модель gpt-5 | да | да |
| `ANTHROPIC_API_KEY` | `anthropic` | да, Claude Sonnet 5.5 | только если есть и ключ OpenAI | да* |
| `MOONSHOT_API_KEY` | `moonshot` | да, Kimi K3.1 Pro | только если есть и ключ OpenAI | да* |

Голосовые переводит в текст только OpenAI. Без ключа OpenAI бот на голосовое вежливо ответит:
«голосовые понимаю только с ключом OpenAI — напишите текстом». Другие нейросети (DeepSeek, Gemini
и прочие) бот не понимает.

\* Если поиск недоступен (у Claude его может выключить администратор организации, у Kimi он
бывает недоступен), бот работает без него — с задачами это не мешает.

**Как устроено.** Бот входит в Таску отдельной учётной записью и работает ТОЛЬКО от имени того,
кто с ним переписывается: связка «человек в Телеграме ↔ пользователь Таски» создаётся один раз
по коду, дальше права проверяются как у самого человека. Чужие задачи бот не видит.

### Что понадобится

1. **Бот в Телеграме.** Напишите [@BotFather](https://t.me/BotFather), команда `/newbot`, получите токен.
2. **Учётка для бота в Таске.** Одна команда: `bash scripts/agent-account.sh` — заведёт
   служебного пользователя `agent@taska.local` и сам впишет его пароль в `.env`. Руками то же
   самое: аватар → «Команда» → добавить. Учётка служебная и в списке людей не показывается —
   так задумано. Повторный запуск — новый пароль агенту: прежние входы агента закрываются,
   а уже запущенного бота скрипт сам перезапускает, чтобы тот взял новый пароль из `.env`.
3. **Ключ нейросети** — один из трёх: OpenAI (platform.openai.com), Claude (platform.claude.com)
   или Kimi (platform.kimi.ai). Поставьте ему потолок расходов.

### Настройка

В `.env`:

```
AGENT_EMAIL=agent@taska.local
AGENT_PASSWORD=пароль_этой_учётки
TELEGRAM_BOT_TOKEN=токен_от_BotFather

# одна нейросеть на выбор — оставьте нужный блок
AI_PROVIDER=openai
OPENAI_API_KEY=ключ_OpenAI

# AI_PROVIDER=anthropic
# ANTHROPIC_API_KEY=ключ_Claude

# AI_PROVIDER=moonshot
# MOONSHOT_API_KEY=ключ_Kimi
```

Модель бот выбирает сам. Заменить её можно строкой `AGENT_MODEL=` — только моделью той же
нейросети: если там осталась модель другой (например, `gpt-5` при Claude), бот её не возьмёт
и скажет об этом в журнале. Ключ OpenAI можно оставить и при Claude или Kimi — тогда бот
будет понимать голосовые. Этот ключ бот проверяет при запуске: если OpenAI его не принимает,
голосовые выключаются, а в журнале написано почему.

Запуск (бот не поднимается вместе с остальным — только по просьбе):

```bash
docker compose --profile bot up -d
docker compose logs -f bot
```

Сразу после запуска бот сам проверяет и Телеграм, и нейросеть. Что не так — видно в журнале
понятными словами («ключ не подошёл», «на счёте нет денег», «не пускает из страны сервера»),
а человеку в Телеграме бот отвечает тем же. Для портала обучения бот пишет и короткие строки
`BOT_STATUS …` — секретов в них нет.

Если в журнале «где-то запущен второй экземпляр бота» — этим же токеном пользуется другой
сервер (например, старый). Остановите бота там: одним токеном может работать только один бот.
Если же в журнале «у бота был включён вебхук» — токен раньше отдавали другой программе; бот сам
выключит вебхук и продолжит работу.

Пока Таска запускается (первые минуту-две), бот уже принимает сообщения и ответит на них,
как только Таска поднимется. Если модель думает дольше полутора минут, бот прерывает ход и
говорит, что успел сделать, — чтобы при повторе не появилось двух одинаковых задач.

### Как подключается человек

1. Открывает Таску → аватар → «Профиль» → «Подключить телеграм».
2. Видит код из шести цифр и присылает его боту в личку.
3. Бот отвечает «Готово» — с этого момента понимает просьбы про задачи.

Отключить можно там же, в профиле. Пароль в переписке не звучит ни разу.

### Голосовые сообщения

Боту можно надиктовать: «поставь задачу купить билеты во вторник в девять утра». Он скачает запись,
переведёт её в текст и покажет, что расслышал, прежде чем действовать.

Нужен ключ OpenAI (`OPENAI_API_KEY`) — при любой нейросети для текста: у Claude и Kimi
распознавания речи нет. Выключается одной строкой в `.env`:

```
AGENT_VOICE=off
```

Telegram своей расшифровки ботам не отдаёт (она есть только в приложении, у премиум-подписки),
поэтому речь распознаёт сам бот. Минута записи стоит доли цента.

### Проверка без модели

Связь бота с Таской проверяется отдельно — вход, работа от имени человека, создание, перенос,
завершение и запрет на задачу без даты:

```bash
docker compose run --rm bot npm run selftest -- <ваш_telegram_id>   # связь с Таской
docker compose run --rm bot npm run checkmsg                        # бот отвечает на любое сообщение
docker compose run --rm bot npm run tryvoice -- /app/запись.ogg      # распознавание речи
docker compose run --rm bot npm run checkproviders                  # OpenAI, Claude и Kimi без настоящих ключей
```

`checkproviders` поднимает поддельные Телеграм, Таску и нейросети у себя внутри и прогоняет бота:
задачу из текста с каждой нейросетью, голосовые, ошибки ключа и второй экземпляр бота.

## CRM для примера (необязательно)

Учебный раздел «CRM» в левом меню Таски: показывает, как в ту же систему добавить ещё одну
часть бизнеса. Внутри три вкладки:

- **Сделки** — воронка по этапам: «Новая» → «Выявление потребности» → «КП отправлено» →
  «Переговоры» → «Счёт выставлен» → «Оплачено» / «Проиграна». На компьютере карточку
  перетаскивают в другой этап, на телефоне — открывают и нажимают нужный этап. Сверху —
  сколько сделок в работе и на какую сумму; кнопка «Мои» оставляет только свои сделки.
- **Клиенты** — компании с контактным лицом, телефоном и почтой; в карточке клиента видны его сделки.
- **Товары** — короткий прайс в рублях. Цены меняет только администратор.

Все сотрудники видят всех клиентов и все сделки. Наблюдатель только смотрит.

Пример данных — вымышленный торговый дом «Плёнка и Короб» (упаковка и расходники для складов):
12 клиентов, 18 сделок, 18 товаров. Почты в зоне `.example`, телефоны `+7 900 000-…`.

**По умолчанию CRM выключена** — без неё Таска выглядит и работает как раньше. Управление —
одним скриптом в папке Таски:

```bash
bash scripts/crm-demo.sh on            # включить раздел и загрузить пример (если в CRM пусто)
bash scripts/crm-demo.sh off           # выключить раздел; данные CRM остаются в базе
bash scripts/crm-demo.sh reset --yes   # стереть данные CRM и загрузить пример заново
bash scripts/crm-demo.sh clear --yes   # стереть данные CRM, раздел остаётся
bash scripts/crm-demo.sh status        # включена ли и сколько записей
```

`on` и `off` перезапускают api (в `.env` меняется строка `CRM_DEMO`) — минута-две, Таска это
время не отвечает. Потом обновите страницу (Ctrl+Shift+R). Скрипт трогает только таблицы `crm_*`:
люди, задачи и метки остаются как были.

Если Таска стоит давно и скрипта `scripts/crm-demo.sh` нет — сначала обновите её с GitHub. Команды
выполняются **на сервере**, не на ноутбуке. С ноутбука (Windows или Mac) это одна строка — она
обновляет Таску, только если вы сами её не правили, и сразу включает CRM:

```bash
ssh taska 'cd /root/taska-edu || exit 1; [ -d .git ] || { echo "СТОП: Таска поставлена не через git clone — обновить нечем"; exit 1; }; git fetch -q || { echo "СТОП: GitHub не ответил — ничего не менял"; exit 1; }; if [ -n "$(git status --porcelain --untracked-files=no)" ] || ! git merge-base --is-ancestor HEAD @{u}; then echo "СТОП: в Таске есть ваши правки — ничего не менял:"; git status --short --untracked-files=no; git log --oneline @{u}..HEAD; exit 1; fi; git pull -q --ff-only && bash scripts/crm-demo.sh on'
```

Что она проверяет перед обновлением:
- Таска — копия с GitHub (папка `.git` на месте);
- вы не меняли файлы Таски (`git status`) и не сохраняли в ней своих коммитов.

Если что-то из этого не так, команда пишет «СТОП», называет ваши файлы и **ничего не меняет**. Тогда
сначала решите, что делать с правками (сохранить копию, перенести), и только потом обновляйте.
Файл `.env` с паролями git не трогает — он в списке исключений.

Если `on` пишет «api не поднялся» — журнал сервера: `docker compose logs api --tail 50`
(в папке Таски на сервере).

## Обслуживание

```bash
docker compose ps                  # что запущено
docker compose logs api --tail 50  # журнал сервера
docker compose restart api         # перезапустить сервер после правок кода
docker compose down                # остановить (данные остаются)
docker compose down -v             # остановить и СТЕРЕТЬ базу вместе с файлами
```

Корзина и архив чистятся сами, раз в сутки: удалённое стирается насовсем через 30 дней
(`TRASH_DAYS`), завершённое — через год (`ARCHIVE_DAYS`). Оба срока меняются в `.env`.

Копию базы снимает `scripts/backup.sh`: делает дамп, сжимает, **проверяет, что архив не битый**,
удаляет копии старше 30 дней (`BACKUP_KEEP_DAYS` в `.env`) и, если настроен телеграм-бот,
пишет администратору — и когда копия готова, и когда не вышла. Строка для `crontab -e`
(каждую ночь в 3:20):

```
20 3 * * * cd /путь/к/taska-edu && bash scripts/backup.sh >> backups/backup.log 2>&1
```

Проверить сейчас: `bash scripts/backup.sh` — в `backups/` появится файл с сегодняшней датой.

Вложения (файлы задач) лежат в томе MinIO `taska-edu_miniodata` и в ночную копию не входят.
Их забирает ноутбук — см. «Копия на ноутбук» ниже. ⚠️ Раньше здесь была команда с томом
`taska-edu_minio`: такого тома нет, docker молча создавал пустой, и архив выходил пустым.
Если вы её где-то записали — удалите.

Резервная копия базы вручную:

```bash
docker compose exec -T postgres pg_dump -U taska taska > backup.sql
```

## Копия на ноутбук

Ночная копия лежит на том же сервере. Случится беда с сервером — пропадут и база, и копии.
Поэтому ноутбук каждый день сам забирает к себе свежую копию: базу и файлы задач.

**Что и куда.** Папка `TaskaBackup` в домашней папке (Mac: Finder → «Переход» → «Домой»;
Windows: `C:\Users\имя\TaskaBackup`):

| Что | Как |
|---|---|
| `taska-ГГГГ-ММ-ДД.sql.gz` | копия базы: свежая ночная копия с сервера, раз в день; хранится 30 последних |
| `files/` | файлы задач (договоры, фото, аватары) — зеркало хранилища; докачивается только новое и изменённое. Удалённое на сервере остаётся здесь ещё 30 дней |
| `Последняя копия.txt` | когда была последняя копия и всё ли в порядке — простыми словами |
| `журнал.txt` | что делалось и когда (последние 1000 строк) |
| `.state/` | служебное, не трогать |

⚠️ В `files/` — не сами договоры, а хранилище MinIO как оно лежит на диске (папки с `xl.meta`).
Открыть договор прямо оттуда нельзя: папку целиком возвращают в Таску (см. «Вернуть файлы задач»).

**Когда.** Mac проверяет сервер каждый час, пока не спит, и сразу после входа в систему; после сна —
сразу как проснётся. Windows — так же: каждый час, при входе и «как можно скорее» после пропуска,
в том числе от батареи. Если копия за сегодня уже есть, ноутбук сервер не трогает.

**Что ноутбук делает на сервере.** Только читает: список копий, контрольные суммы, скачивание.
Записывает лишь две отметки: `backups/.laptop-ok` (забрал базу) и `backups/.laptop-files-ok`
(сверил файлы задач). По ним `backup.sh` в ночном отчёте в Телеграм пишет «ноутбук не забирал копию
N дней» или «ноутбук берёт базу, а файлы задач не забирал N дней» — это работает, даже если
ноутбук сломан, потерян или его задачу выключили.

**Если связь медленная.** Первая полная копия файлов задач может идти часами — это нормально.
Оборвалась (сон, выключение, на Windows — предел задачи 4 часа) — скачанное не пропадает:
следующий запуск кладёт готовые файлы на место и докачивает остальное.

### Поставить (или обновить)

Сначала на сервере — свежие скрипты, точечно, не трогая остальной код (ваши правки останутся):

```bash
cd /root/taska-edu && git fetch && git checkout origin/main -- scripts/laptop scripts/backup.sh scripts/restore.sh
```

Потом на ноутбуке — установщик. Он сам заберёт остальные файлы, сделает первую копию, поставит
расписание и проверит его; укладывается в полторы минуты. Нужен вход `ssh taska`
(шаг «Подключить помощника»). Запускать от своего пользователя, вне песочницы помощника.

Mac (Терминал):

```bash
scp taska:/root/taska-edu/scripts/laptop/install-mac.sh /tmp/ && bash /tmp/install-mac.sh
```

Windows (PowerShell, права администратора не нужны).
Проверено на живой Windows 11 (ARM, в Parallels на Mac, 12.11.2026): установка, ежечасные запуски,
докачка, сбои, удаление и переустановка во время копии; 16.11.2026 — ещё раз на живой Windows 11
с включённым Защитником Windows: он ничего не заблокировал. С именем пользователя на русском
ещё не проверяли — если копия не встаёт, держите её вручную (ниже, «Скачать копию вручную»):

```powershell
cd $env:TEMP
scp taska:/root/taska-edu/scripts/laptop/install-windows.ps1 .
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install-windows.ps1
```

Повторный запуск безопасен — так же копия и обновляется. Сами копии он не трогает.
Если на Windows скрытый запуск запрещён (рабочий ноутбук, антивирус), добавьте `-Window visible`:
окно PowerShell будет коротко появляться свёрнутым раз в час.

macOS 13 и новее при установке показывает уведомление о фоновом объекте «taska-backup.sh» и
добавляет его в «Системные настройки → Основные → Объекты входа». Это и есть копия — не выключайте.

Ответ установщика:

- «Готово» (код 0) — всё стоит, первая копия скачана.
- «Готово», а под ним «НО ПЕРВАЯ КОПИЯ НЕ ВЫШЛА: …» (код 2) — расписание стоит и дальше работает
  само, не вышла только первая копия. После двоеточия — первая строка `Последняя копия.txt` (без
  «ВНИМАНИЕ:»). Неполадка на этом компьютере или со связью выглядит так: «НО ПЕРВАЯ КОПИЯ НЕ ВЫШЛА:
  копия не обновлялась с ДД.ММ.ГГГГ: нет связи с сервером…» — причина в конце строки, после
  двоеточия за датой. Беда на сервере идёт без «копия не обновлялась с …:» — тогда вся строка после «НЕ ВЫШЛА:»
  и есть причина: «на сервере нет ни одной ночной копии…», «ночная копия на сервере не делается с …».
  Что делать — по таблице в «Проверить» ниже; если в строке есть «Скажите помощнику: …» — отдайте
  помощнику эту фразу. «не уложилась во время установки (медленная связь)» — ничего не чинить:
  копию доделает расписание в течение часа. «см. строки выше» — причина в строках первой копии над «Готово».
  Установку повторять не нужно — расписание уже стоит.
- «НЕ УСТАНОВЛЕНО: …» — что исправить и повторить.
- «ПОСТАВЛЕНО, НО НЕ ПРОВЕРЕНО» (код 4) — расписание стоит, но на медленной связи не хватило 90 с,
  чтобы дождаться его первого запуска: ничего не чинить, через 5 минут открыть `Последняя копия.txt`.

Linux и WSL установщик не поддерживает — держите копию вручную (ниже, «Скачать копию вручную»).

### Проверить

Откройте `Последняя копия.txt`. Если всё хорошо — там дата последней копии. Если нет — первая строка
начинается с «ВНИМАНИЕ:» и говорит, что случилось и что сделать. Если копии нет три дня (а при беде
на сервере — сразу), ноутбук раз в сутки показывает окно с тем же текстом.

| В «Последняя копия.txt» | Что делать |
|---|---|
| нет связи с сервером | проверьте интернет; рабочий Wi-Fi иногда закрывает вход на серверы. Копия сделается сама |
| ключ больше не подходит | «Подключить помощника» на другом компьютере отключает ключ этого. Повторите на этом компьютере шаг «Подключить помощника» |
| сервер переустановлен или заменён | шаг «Подключить помощника» |
| нет входа «ssh taska» | шаг «Подключить помощника» |
| ночная копия на сервере не делается / битая | на сервере: `crontab -l` (есть ли строка с `backup.sh`), `df -h` (не кончился ли диск), `bash scripts/backup.sh` руками |
| на сервере старая версия скриптов копии | повторите «Поставить (или обновить)» |
| в Телеграм: «ноутбук берёт базу, а файлы задач не забирал» | на ноутбуке строка «Файлы задач сейчас:» в `Последняя копия.txt` говорит, почему (чаще всего — мало места) |

Версия скриптов на ноутбуке — в первой строке статуса; актуальная — `scripts/laptop/VERSION`.

### Выключить

Одна команда. Убирает расписание, скрипты и отметку на сервере; сами копии остаются в `TaskaBackup`.

```bash
bash ~/.taska-backup/uninstall-mac.sh                                                    # Mac
```

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\.taska-backup\uninstall-windows.ps1"   # Windows
```

### Вернуть базу из копии

⚠️ Возврат заменяет ВСЁ, что сейчас в Таске: сделанное после копии пропадёт.

1. Перенесите копию с ноутбука на сервер. Mac:
   `scp ~/TaskaBackup/taska-2026-11-12.sql.gz taska:/root/taska-edu/backups/from-laptop.sql.gz`.
   Windows — из самой папки, чтобы русское имя пользователя не попало в команду:
   `cd $env:USERPROFILE\TaskaBackup` и `scp taska-2026-11-12.sql.gz taska:/root/taska-edu/backups/from-laptop.sql.gz`.
2. На сервере: `cd /root/taska-edu && bash scripts/restore.sh backups/from-laptop.sql.gz` — скрипт проверит
   файл и скажет, что будет, но ничего не сделает.
3. Только после «да» человека: `bash scripts/restore.sh backups/from-laptop.sql.gz --yes`.

Что делает `restore.sh`: проверяет файл (целый ли архив, внутри ли база) ДО того, как что-то стирать;
сохраняет текущую базу в `backups/before-restore-ГГГГММДД-ЧЧММСС.sql.gz` (если вернули не ту копию —
верните эту так же); останавливает api (и бота, если он есть), пересоздаёт базу, заливает копию,
запускает обратно и ждёт ответа Таски. При любом сбое api запускается обратно сам.
Если текущая база сломана так, что сохранить её нельзя, скрипт остановится и подскажет ключ
`--without-safety-copy` — его ставить только с согласия человека.

### Вернуть файлы задач

Нужны на сервере тот же `.env` (пароли `MINIO_ROOT_*` — из менеджера паролей) и запущенная Таска.

1. Перенесите с ноутбука папку `files` и список удалённого на сервере (его `restore.sh` пропустит,
   чтобы не засорять диск файлами, на которые в базе уже нет ссылок). Mac:
   `cd ~/TaskaBackup && scp -r files taska:/root/taska-edu/backups/restore-files && scp .state/files.gone taska:/root/taska-edu/backups/restore-files.gone`
   (Windows: `cd $env:USERPROFILE\TaskaBackup`, потом те же две команды `scp`).
2. На сервере: `bash scripts/restore.sh --files backups/restore-files`, затем с `--yes` после «да» человека.
   Нет `restore-files.gone` — скрипт предупредит: вернутся и файлы, удалённые за последние 30 дней.
3. Откройте задачу с вложением — файл должен скачиваться. `backups/restore-files` и
   `restore-files.gone` потом удалите: диск сервера маленький.

Возвращается и на тот же сервер, и на новый, с чистым хранилищем (проверено на стенде).

### Скачать копию вручную

Когда установщик не встал (рабочий ноутбук с запретами, антивирус не пускает задачу), а также Linux
и WSL — держите копию вручную: раз в неделю промпт «Скачать копию вручную» из памятки. Помощник делает так:

1. Создаёт папку `TaskaBackup` в домашней папке, если её нет, и переходит в неё
   (Mac, Linux: `mkdir -p ~/TaskaBackup && cd ~/TaskaBackup`; Windows:
   `New-Item -ItemType Directory -Force "$env:USERPROFILE\TaskaBackup" | Out-Null; Set-Location -ErrorAction Stop "$env:USERPROFILE\TaskaBackup"`).
   Перейти не вышло — **ничего не качает** и говорит почему: иначе копия ляжет неизвестно куда.
2. `ssh taska ls -1 /root/taska-edu/backups` → самый свежий `ГГГГ-ММ-ДД.sql.gz`.
3. `scp` из самой папки `TaskaBackup` (на Windows так русское имя пользователя не попадает в команду)
   под именем `taska-ГГГГ-ММ-ДД.sql.gz` с той же датой, например
   `scp taska:/root/taska-edu/backups/2026-11-12.sql.gz taska-2026-11-12.sql.gz`. С таким именем копию
   видит и установщик, если он потом встанет: учитывает её среди 30 хранимых и не качает её второй раз.
4. Сверяет контрольную сумму с сервером (`sha256sum` там, `shasum -a 256` на Mac, `sha256sum` на Linux,
   `Get-FileHash` на Windows). Не сошлась (оборвалась связь и т. п.) — удаляет этот файл и качает заново:
   недокачанная копия с правильным именем выглядела бы для установщика как готовая.

Вручную копируется только база: файлы задач — только установщиком.

### Безопасность

Копия — это данные команды в открытом виде: почты, тексты задач, файлы. Если ноутбук украдут,
утечёт столько же, сколько с ключом к серверу. Поставьте пароль на вход и включите шифрование
диска: FileVault на Mac, BitLocker (или «Шифрование устройства») на Windows. Не кладите
`TaskaBackup` в облачные папки (OneDrive, iCloud Drive, «Документы» с синхронизацией).

## Если что-то не так

| Симптом | Причина и что делать |
|---|---|
| `port is already allocated` | порт занят другой программой — поменяйте `HTTP_BIND` в `.env` |
| `401 Unauthorized` или `pull access denied` на minio | официальный образ MinIO закрыт — в `docker-compose.yml` образ minio должен быть `pgsty/minio` (строка `image: pgsty/minio:latest@sha256:…`, дайджест закрепляет проверенную сборку — не убирайте его) |
| Страница открылась пустой | правили `web/index.html` — запустите `node scripts/check-web.js` |
| Вход не пускает | сначала `bash scripts/first-login.sh` — адрес, логин и пароль администратора, пока его не меняли. Код 3 — пароль уже меняли (или базу вернули из копии): входите с тем, что сохранили; нет его — `bash scripts/admin-password.sh` задаст новый, ничего не стирая (после «да» человека). Причина отказа словами — в `docker compose logs api` |
| Выкинуло на экран входа «Сессия истекла» | под этим логином сменили пароль или его выключили в «Команде» — прежние входы закрываются. Войдите с новым паролем |
| Под `admin` с паролем `123456` не войти | Таску ставили до 16.11: пароль заменён на новый — `bash scripts/first-login.sh` (см. «Если ставили Таску до 16.11») |
| Под `manager` или `user` не войти | так задумано: у демо-сотрудников нет пароля, его задаёт администратор в «Команде» |
| После правки кода ничего не изменилось | `docker compose restart api`, а страницу обновите с Ctrl+Shift+R |

⚠️ **Правка `.env` доезжает не сама.** Docker подставляет переменные в момент СОЗДАНИЯ контейнера,
поэтому после изменения `.env` нужен `docker compose up -d --force-recreate`, иначе сервис
продолжит работать со старыми значениями.

## Безопасность

- `.env` не попадает в репозиторий (он в `.gitignore`) — так и оставьте.
- Пароли и ключи держите только в `.env`, не в коде.
- На сервере наружу нужны только 80 и 443. База, хранилище и API сидят во внутренней сети docker.
- Вход (сессия) живёт 90 дней и продлевается сам, но каждое действие сверяется с базой: смена пароля
  или выключение сотрудника закрывает все его открытые входы сразу. Закрыть входы ВСЕМ разом
  (например, если `.env` попал в чужие руки): новый `JWT_SECRET` в `.env` (`openssl rand -hex 32`)
  и `docker compose up -d --force-recreate api` — войти заново придётся всем, включая вас.
