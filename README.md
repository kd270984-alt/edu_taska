# Таска · учебная версия

Планировщик задач команды: один экран — календарь. У каждого человека свои задачи,
задачи можно поручать друг другу, переносить по дням, обсуждать и складывать в архив.

Продукт ставится на ваш сервер целиком: база, хранилище файлов, API и веб-страница.
Ничего внешнего, кроме адреса вашего сайта, не нужно.

---

## Что внутри

| Часть | Что это |
|---|---|
| `web/index.html` | всё приложение: календарь, карточки задач, поиск, архив, профиль |
| `api/` | сервер: вход, задачи, метки, комментарии, вложения, пользователи |
| `api/migrations/` | схема базы (применяется сама при первом запуске) |
| `docker-compose.yml` | весь стек: PostgreSQL, Redis, MinIO, API, Caddy |
| `Caddyfile` | веб-сервер: раздаёт страницу, проксирует `/api` и `/ws`, сам получает HTTPS |
| `scripts/check-web.js` | проверка фронта перед выкладкой (ловит битый JS) |

## Что нужно на машине

- Docker и Docker Compose (Docker Desktop на Mac/Windows, `docker` + плагин compose на Linux)
- 2 ГБ свободной памяти и 5 ГБ диска
- Для сервера: домен, направленный на его адрес (для HTTPS), и открытые порты 80 и 443

## Запуск на своей машине (5 минут)

```bash
cp .env.example .env
```

Откройте `.env` и заполните пустые строки. Пароли придумайте любые длинные, например так:

```bash
openssl rand -hex 24
```

Заполнить нужно `POSTGRES_PASSWORD` (тот же пароль подставьте внутрь `DATABASE_URL`),
`MINIO_ROOT_PASSWORD` и `JWT_SECRET`. Остальное на своей машине оставьте как есть.

```bash
docker compose up -d
```

Первый запуск качает образы — это пара минут. Готово, когда команда ниже отвечает `"ok":true`:

```bash
curl http://127.0.0.1:8088/api/health
```

Откройте **http://localhost:8088**.

Пароль первого администратора система создаёт сама и печатает в журнале:

```bash
docker compose logs api | grep ADMIN_BOOTSTRAP
```

Войдите под `admin@example.com` с этим паролем и сразу смените его в профиле (щёлкните по своему
аватару слева). Остальных людей заводит администратор в разделе «Команда».

## Запуск на сервере

1. **Адрес.** Нужен домен, по которому сервер видно из интернета. Два пути:
   - свой домен — направьте его A-записью на адрес сервера;
   - бесплатный адрес **sslip.io** — это IP сервера, записанный через дефисы, плюс `.sslip.io`.
     Для сервера `89.207.249.162` адрес будет `89-207-249-162.sslip.io`. Регистрировать
     и настраивать ничего не нужно, он работает сразу.
2. **Папка.** Положите проект на сервер в папку `taska-edu` — например
   `git clone <адрес репозитория> taska-edu`. Имя папки важно: docker берёт от него имена
   томов (`taska-edu_minio`), и команды из раздела «Обслуживание» рассчитаны на него.
3. Создайте `.env` так же, как выше, и добавьте в него:

```
APP_HOST=89-207-249-162.sslip.io    # свой домен или адрес sslip.io; без http:// и без / на конце
ACME_EMAIL=почта@для-сертификата
HTTP_BIND=0.0.0.0:80
HTTPS_BIND=0.0.0.0:443
```

4. `docker compose up -d` — Caddy сам получит сертификат Let's Encrypt.
5. Проверка на самом сервере. Caddy отвечает только на свой домен, поэтому обычный
   `curl http://127.0.0.1/api/health` вернёт 404 — это не поломка. Спрашивайте с заголовком:

```bash
curl -s -H "Host: 89-207-249-162.sslip.io" http://127.0.0.1/api/health
```

6. Откройте `https://` и свой адрес. Замок появляется не сразу: сертификат выдаётся
   за несколько секунд после первого обращения.

**Перед тем как открывать сервер людям — четыре дела:**

1. Войдите первым администратором: временный пароль система печатает в журнале один раз —
   `docker compose logs api | grep ADMIN_BOOTSTRAP`. Сразу смените его в своём профиле.
2. Закройте на сервере всё, кроме 22, 80 и 443:
   `ufw allow 22/tcp && ufw allow 80,443/tcp && ufw enable`.
   ⚠️ Порт 22 разрешайте ПЕРВЫМ и не пропускайте его: это SSH, без него включённый файрвол
   отрежет вас от собственного сервера. База, хранилище и API сидят во внутренней сети
   docker и наружу не смотрят.
3. Заведите резервные копии по расписанию, а не руками (см. «Обслуживание»).
4. Проверьте, что `JWT_SECRET` в `.env` — длинная случайная строка, а не оставшаяся от примера.

## Помощник в Телеграме (необязательно)

К Таске можно подключить бота: человек пишет ему в личку обычными словами — «что у меня
сегодня?», «добавь задачу позвонить клиенту на завтра в 11», «перенеси смету на пятницу»,
«заверши планёрку» — а бот делает это в Таске от его имени. Он умеет и поискать в интернете,
если вопрос не про задачи.

**Как устроено.** Бот входит в Таску отдельной учётной записью и работает ТОЛЬКО от имени того,
кто с ним переписывается: связка «человек в Телеграме ↔ пользователь Таски» создаётся один раз
по коду, дальше права проверяются как у самого человека. Чужие задачи бот не видит.

### Что понадобится

1. **Бот в Телеграме.** Напишите [@BotFather](https://t.me/BotFather), команда `/newbot`, получите токен.
2. **Учётка для бота в Таске.** Аватар → «Команда» → добавить, например `agent@taska.local`.
3. **Ключ модели** — из личного кабинета OpenAI. Поставьте ему потолок расходов.

### Настройка

В `.env`:

```
AGENT_EMAIL=agent@taska.local
AGENT_PASSWORD=пароль_этой_учётки
TELEGRAM_BOT_TOKEN=токен_от_BotFather
OPENAI_API_KEY=ключ_модели
AGENT_MODEL=gpt-5
```

Запуск (бот не поднимается вместе с остальным — только по просьбе):

```bash
docker compose --profile bot up -d
docker compose logs -f bot
```

### Как подключается человек

1. Открывает Таску → аватар → «Профиль» → «Подключить телеграм».
2. Видит код из шести цифр и присылает его боту в личку.
3. Бот отвечает «Готово» — с этого момента понимает просьбы про задачи.

Отключить можно там же, в профиле. Пароль в переписке не звучит ни разу.

### Голосовые сообщения

Боту можно надиктовать: «поставь задачу купить билеты во вторник в девять утра». Он скачает запись,
переведёт её в текст и покажет, что расслышал, прежде чем действовать.

Отдельной настройки не нужно — работает тем же ключом OpenAI. Выключается одной строкой в `.env`:

```
AGENT_VOICE=off
```

Telegram своей расшифровки ботам не отдаёт (она есть только в приложении, у премиум-подписки),
поэтому речь распознаёт сам бот. Минута записи стоит доли цента.

### Проверка без модели

Связь бота с Таской проверяется отдельно — вход, работа от имени человека, создание, перенос,
завершение и запрет на задачу без даты:

```bash
docker compose run --rm bot npm run selftest -- <ваш_telegram_id>   # связь с Таской
docker compose run --rm bot npm run checkmsg                        # бот отвечает на любое сообщение
docker compose run --rm bot npm run tryvoice -- /app/запись.ogg      # распознавание речи
```

## Обслуживание

```bash
docker compose ps                  # что запущено
docker compose logs api --tail 50  # журнал сервера
docker compose restart api         # перезапустить сервер после правок кода
docker compose down                # остановить (данные остаются)
docker compose down -v             # остановить и СТЕРЕТЬ базу вместе с файлами
```

Корзина и архив чистятся сами, раз в сутки: удалённое стирается насовсем через 30 дней
(`TRASH_DAYS`), завершённое — через год (`ARCHIVE_DAYS`). Оба срока меняются в `.env`.

Копию базы полезно снимать по расписанию. Строка для `crontab -e` (каждую ночь в 3:20,
хранить месяц):

```
20 3 * * * cd /путь/к/taska-edu && docker compose exec -T postgres pg_dump -U taska taska | gzip > backups/$(date +\%F).sql.gz && find backups -name '*.sql.gz' -mtime +30 -delete
```

Вложения лежат в томе MinIO — его копируют отдельно (`docker run --rm -v taska-edu_minio:/data -v $PWD/backups:/b alpine tar czf /b/minio-$(date +%F).tgz /data`).

Резервная копия базы вручную:

```bash
docker compose exec -T postgres pg_dump -U taska taska > backup.sql
```

## Если что-то не так

| Симптом | Причина и что делать |
|---|---|
| `port is already allocated` | порт занят другой программой — поменяйте `HTTP_BIND` в `.env` |
| `pull access denied` на minio | образ берётся с `quay.io/minio/minio`, проверьте строку `image:` в `docker-compose.yml` |
| Страница открылась пустой | правили `web/index.html` — запустите `node scripts/check-web.js` |
| Вход не пускает | смотрите `docker compose logs api`, там причина отказа словами |
| После правки кода ничего не изменилось | `docker compose restart api`, а страницу обновите с Ctrl+Shift+R |

⚠️ **Правка `.env` доезжает не сама.** Docker подставляет переменные в момент СОЗДАНИЯ контейнера,
поэтому после изменения `.env` нужен `docker compose up -d --force-recreate`, иначе сервис
продолжит работать со старыми значениями.

## Безопасность

- `.env` не попадает в репозиторий (он в `.gitignore`) — так и оставьте.
- Пароли и ключи держите только в `.env`, не в коде.
- На сервере наружу нужны только 80 и 443. База, хранилище и API сидят во внутренней сети docker.
